# 12 — Skill owners

Always on. Discovery defaults only. Before selecting a listed skill, load [skill routing](11-skill-routing.md) and its smallest matching reference, if any. Detailed routes and explicit compatible requests take precedence. For name collisions, prefer a compatible shared-tree skill; host requirements still apply.

Here, **named** means the user explicitly invokes the skill.

- Browser: `04-host-tooling.md` selects the browser and automation method.
- Diagnosis: `diagnosing-bugs`; `debug` named.
- Substantial diff review: `code-review`, plus `better-interface` for UI.
- Codebase audit or plans: `improve`.
- Module or API boundary: `system-design`; `codebase-design` vocabulary only.
- ADRs: `architecture`, in the repository's existing format.
- Plan stress-test: `grilling`.
- Interface build: `impeccable`; specialized direction follows [creative routing](routing/interface/creative.md).
- Web platform: `modern-web-guidance` on the [frontend route](routing/frontend-specialists.md).
- Interface review: `better-interface` or one `better-*` domain; `interface-review` named.
- Motion: [motion routing](routing/motion.md). Systems and tokens: [system/content routing](routing/design-system.md).
- Commits and PR titles: `02-attribution.md`; `git-commit` named.
- Research: `research` for delegated work with a requested saved report; ordinary lookups follow `31-current-info.md`.
- PDF: `pdf-harvester` for extraction or RAG.
- Skill authoring: `skill-architect`; `skill-creator` named.

# 99 — Anti-patterns

Always on. These judgment failures are not defined elsewhere; workflow, safety, code, and interface constraints remain in their owning rules.

- Follow an established codebase pattern when it resolves the choice; offer alternatives only for a material trade-off.
- State honest uncertainty once instead of burying it in hedging.
- Preserve error handling, logging, and edge-case logic unless evidence shows it is obsolete.
- Flag ambiguous brand, design, or product intent instead of inventing it.
